# Hotfix del launcher (21-oct-2026)

El launcher instalado en el stick (`com.suop.tvlauncher`, build debug del
20-oct) **no abre ninguna app**, el desplegable de «Entradas» es
inalcanzable y «Wi-Fi» no hace nada. Diagnóstico hecho contra el stick real
(`192.168.3.26:5555`, `MiTV_AESP0`, Android 9) y arreglado sobre el código
del repo, que se instala como `es.hugoperezvigo.tvlauncher` 1.1.

## 1. Qué pasaba en el stick

| Síntoma | Causa |
|---|---|
| Las teselas no abren nada | `AppAdapter` no ponía `setOnClickListener` y `activateFocused()` solo sabía actuar sobre las tres pastillas de la barra. `AppCatalog.launch()` no lo llamaba nadie: código muerto. |
| «Entradas» sale un menú con 3 filas y no se puede entrar | Las filas del desplegable nunca recibían el foco: nuestro `dispatchKeyEvent` se come el D-pad y el framework no busca el siguiente foco. Al pulsar Abajo el foco volvía a la rejilla y el panel se quedaba abierto encima. |
| Las 3 filas son «Live TV» | No son entradas: son los servicios de *preview* de Play Películas y SkyShowtime, que el sistema registra como `TYPE_TUNER`. El stick no tiene HDMI ni tuner propios: el HDMI es del televisor. |
| «Wi-Fi» no hace nada | `btnWifi.setOnClickListener(v -> { /* informativa */ })`: botón muerto. |
| Al volver de una app el foco vuelve a la primera tesela | `loadApps()` se llamaba en cada `onResume` y recreaba el `Navigator`. |
| Las filas de la rejilla se cortan por la mitad al desplazarse | `smoothScrollToPosition` hace el scroll mínimo: deja una fila partida arriba. |
| A veces se abre la app equivocada | Un reposicionamiento de la rejilla (`scrollToPositionWithOffset`) rehace el layout y **recicla la tesela enfocada**: se queda sin foco, el sistema pasa el foco a la primera tesela y la tecla OK abre esa. |

## 2. Qué se cambia

1. **Clic en las teselas.** `AppAdapter` pone `setOnClickListener` y
   `activateFocused()` abre **la app de la tesela enfocada**, mirando su
   posición en la rejilla (`layoutManager.getPosition`), no la que el
   sistema tenga enfocada por error. La tecla OK se consume entera (bajada
   y bajada) para que el framework no dispare un segundo clic.
2. **«Entradas» utilizable.** El desplegable pasa a ser navegable con el
   D-pad (las filas reciben el foco, se ven enfocadas, Atrás y el botón
   izquierdo lo cierran) y solo lista entradas reales:
   - el selector de entradas del sistema, si el sistema tiene uno;
   - la TV en directo (`com.google.android.tv`), que es la entrada real del
     stick;
   - los servicios de previsualización se descartan (`TvInputs.isPreview`).
3. **«Wi-Fi» abre los ajustes de Wi-Fi** del sistema.
4. **Navegación**: el `Navigator` conoce la rejilla y sabe que la última
   fila puede estar incompleta: izquierda desde su primera tesela salta al
   final de la fila de arriba y no se queda el foco en un hueco.
5. **Foco**: el scroll alinea la fila enfocada arriba (filas enteras, sin
   cortes) y es **de píxeles**, no un reposicionamiento: así la tesela no se
   recicla y no se pierde el foco. Al volver de una app se recupera la
   última tesela enfocada.
6. **Catálogo**: una app = una tesela (se descartan las clases
   `*Application` que el sistema devuelve como candidatas) y se quitan los
   permisos que no se usan.

## 3. Verificación en el stick

Todo probado con pulsaciones del mando inyectadas por ADB, con capturas:

| Qué | Resultado |
|---|---|
| OK sobre una tesela | Abre esa app (YouTube, HBO Max, YouTube Music…) |
| «Ajustes» | Abre `com.android.tv.settings/.MainSettings` |
| «Wi-Fi» | Abre `com.android.tv.settings/.connectivity.NetworkActivity` |
| «Entradas» | Abre el desplegable con «Live TV» enfocada; OK abre la TV en directo |
| Volver de una app | El foco vuelve a la última tesela enfocada |
| Desplazarse | La fila enfocada queda entera arriba |
| Última fila (una sola app) | El foco no cae en un hueco; a la izquierda salta al final de la fila de arriba |
| Arranque en frío (tras reiniciar el stick) | Todo lo anterior sigue funcionando |

42 tests unitarios (antes 32): los nuevos cubren la última fila incompleta
del `Navigator` y el filtro de entradas de `TvInputs`.

## 4. Paquete

El stick tenía `com.suop.tvlauncher` (el nombre antiguo, build debug). El
código del repo es `es.hugoperezvigo.tvlauncher`: el hotfix se instala con
el paquete del repo (1.1, release firmado), se pone como HOME y se
desinstala el antiguo.

**El launcher del repo nunca había llegado a la tele**: el 20-oct se
instaló el build debug con el nombre viejo y el APK de `dist/` se
compiló después, sin llegar a instalarse.
